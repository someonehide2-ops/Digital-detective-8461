## 2. Work completed
### Task 6.1 — Basic Git workflow
| Git operation | What it does |
|---|---|
| Check repository status | Shows changed, staged and untracked files. |
| Stage selected changes | Selects changes to be included in the next commit. |
| Create a commit | Saves a snapshot of the staged changes in local repository history. |
| View commit history | Shows previous commits and their messages. |

Staging prepares selected changes for a commit. Committing records the staged snapshot in the repository's history. A commit is local until it is pushed to GitHub.

### Task 6.4 — Git command glossary
| Operation | Explanation |
|---|---|
| Initialise | Starts Git version tracking in a folder. |
| Check status | Shows the state of working-tree and staged changes. |
| Stage | Selects changes for the next commit. |
| Commit | Records staged changes in local history. |
| View history | Displays earlier commits. |
| Create/list branches | Creates a separate line of work or shows existing branches. |
| Switch branches | Changes the current working branch. |
| Publish changes | Pushes local commits to a remote repository. |
| Retrieve remote changes | Fetches or pulls changes from a remote repository. |

## 4. My understanding
Git tracks changes over time. GitHub hosts repositories online. Staging selects changes, commits save them locally, and pushing publishes commits to the remote repository. Branches and Pull Requests support review and collaboration.
